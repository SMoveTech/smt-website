S-Move Dealer — Environment & Configuration Reference

Every environment variable, secret and external endpoint the platform depends on. Set on the Railway service (Variables tab). Values are never stored here — this lists the names, what they do, and where they come from.

Compiled 2026-07-30 from a full grep of process.env across the SMD App source (excluding the obfuscated dist/ build). Confirm against the live Railway variables before relying on it.

14. Legacy / unused — flagged for cleanup

The local .env defines several names that no longer appear anywhere in the current .js source (checked by name only, not value): SMTP_HOST, SMTP_PORT, SMTP_USER, SMTP_PASS (superseded by the Gmail API move), SUPABASE_PUBLISHABLE_KEY, APIFY_TOKEN (the Apify/eBay scraper was retired with buy-to-resell), and SUPABASE_S3_ENDPOINT / SUPABASE_S3_REGION / SUPABASE_S3_ACCESS_KEY_ID / SUPABASE_S3_SECRET_ACCESS_KEY. Worth a decision: remove from .env/Railway, or keep as reserved-for-future and note why.

15. Rotation & handling

  • Never commit secrets — all values live only in Railway Variables (and locally in an untracked .env).
  • The app only ever runs the obfuscated build (npm start → dist/server.js) — env-var behaviour verified in source applies identically at runtime.
  • Stripe has two separate webhook secrets (checkout vs. billing/sponsorship) — re-copy the correct one if either endpoint is recreated.
  • Railway's IPv6 egress is broken for this app too — server.js forces IPv4 DNS resolution and disables Happy-Eyeballs at boot; no separate env var controls this, it's hardcoded.
  • If a key is rotated at the provider, update Railway and redeploy — the app reads env at boot.
