2. Notes & conventions

  • Single-row config tables (monzo_tokens, gmail_tokens, pricing) use a fixed id=1 row.
  • JSONB is used heavily for flexible/nested data (quotes, roles, pricing, absences, payslip data, inventories). Treat as semi-structured; validate on write.
  • Soft-delete: financial and comm data is never hard-deleted — see comm_log_tombstones and the data-safety layer. Never hard-delete financial records.
  • PII-bearing tables (for GDPR mapping): customers, staff_members (bank_details, password_hash), payslips, comm_logs, messages, referrals, company_accounts. See the Data Protection doc.
